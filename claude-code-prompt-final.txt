PIPELINE (one run)
Runs in /api/run. Process accounts in batches of 3 in parallel to stay within Vercel's time limit, and set maxDuration to 60 on the route. One account failing must never stop the others.
For each account:
1. Fetch Google News RSS for its search_phrase. Keep only stories published in the last 3 days. Take at most the 10 most recent. Keep title, link, source name, published date and the description snippet.
2. Remove stories already in seen_stories for this account. Save the new ones to seen_stories.
3. If there are no new stories: set check_status = no_news, set signal_score = floor(previous signal_score / 2), update last_checked_at, and leave signal_summary, outreach_angle and source fields as they were. This is the "going quiet" rule.
4. If there are new stories: make ONE Gemini call for this account. Send the signal guide, the company name, segment and stage, and the list of new stories. Do NOT send arjun_notes, last_contact_date or relationship_read to Gemini. Gemini returns the JSON described in section 6 of the signal guide.
5. If Gemini returns signal_score > 0: write signal_score = max(new score, floor(previous score / 2)), plus trigger_types, signal_summary, outreach_angle, source_url, source_title, signal_found_at = now, last_checked_at = now, check_status = ok.
   If Gemini returns 0: treat it like step 3 (no relevant signal), but with check_status = ok.
6. If the news fetch or Gemini call fails: set check_status = failed and last_checked_at = now, change nothing else, and record the error in the run log.
After all accounts: write the run_log row, then send the Hot List email.

SCHEDULE AND TRIGGERS
- vercel.json cron: Monday and Thursday at 7:00 am India time = "30 1 * * 1,4" (UTC), calling /api/run.
- /api/run accepts the cron call only when the Authorization header equals "Bearer " + CRON_SECRET (this is how Vercel cron authenticates).
- The dashboard has a "Check now and email me" button. It calls a separate server route, /api/run-now, which runs the same pipeline with triggered_by = manual. To prevent abuse, /api/run-now refuses to run if another run started less than 5 minutes ago and shows a friendly message instead. The browser must never see CRON_SECRET.
